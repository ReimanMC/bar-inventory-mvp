La Ramona Inventory MVP - V0.5.6 validation

Scope
- Supabase Storage first-manifest bootstrap after upgrading from legacy latest/daily/weekly backups.
- Missing-object handling for Supabase responses.
- Preservation of V0.5.5 anti-regression rules.

Verified
1. Python syntax/AST compilation: PASS.
2. Missing Storage object returned as HTTP 404: recognized as optional/missing, not connection failure.
3. Missing Storage object returned as HTTP 400 with statusCode=404, error=not_found, message=Object not found, code=NoSuchKey: recognized as optional/missing, not connection failure.
4. Authentication/server errors (401/500): remain real errors and are NOT suppressed.
5. With no manifest, sync falls back to legacy latest/bar_inventory_v3.db for safe comparison.
6. Equal local/legacy latest permits automatic creation of revision slot + manifest.
7. More-complete remote legacy latest still wins during preflight.
8. More-complete local legacy DB can bootstrap remote only through the guarded backup path.
9. Divergent/incomparable local and remote branches remain blocked from overwriting each other.
10. Manifest-based recovery and slot validation remain unchanged after bootstrap.

Root cause fixed
Supabase Storage may return HTTP 400 while the JSON body reports a missing object (statusCode 404 / NoSuchKey). V0.5.5 only treated literal HTTP 404 as a normal missing manifest, which caused first-run protected mode and prevented manifest creation.
